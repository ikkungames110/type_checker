# Repository Instructions

- After making any file modification for the user, commit the change and push it to the configured Git remote.
- If push is not possible, report the reason clearly and leave the working tree state explicit.
- Cloudflare Pages is connected to this GitHub repository. A push to `main` triggers production deployment; verify the matching deployment succeeds and the live site reflects the change before reporting completion. Build: `python3 scripts/build_pages.py`, output: `dist`, production: `https://type-checker.shianstudio.com/`.
- Production uses v8: 40 portraits per gender, eight types with five distinct people each, all generated at age 25. Portraits live in `assets/<gender>/<gender>_001.png` through `040`; records are browser globals in `data/<gender>_faces.js`. Keep images, types, prompts and generation hashes in sync. Prior face sets and obsolete feature plans were deleted; do not restore them.
- Scoring adds one vote to the chosen portrait's type, across eight types. Return all types tied for the highest count in canonical A/R, S/C, Q/V code order; never combine letters to infer a winner or break ties at random. `data/result_types.js` maps types to codes; `data/type_axes.js` defines letter meanings only. Numeric facial features and compatibility tags must not be reintroduced.
- Results show large winning codes, matching characters, and only the meanings of the three letters in each winning code below the face examples. Do not show percentages, vote counts, scoring explanations, or numbered example captions. Recompute results from persisted choices, including old v8 sessions; ignore old winnerId. Original classifications appear in parentheses below each catchy title, aligned right. Female titles end in 顔.
- Quiz choice cards show only portrait images. Do not reveal labels, type names, tags, arrows or scoring hints on those cards.
- Pair different types. The first 20 displayed pairs cover all 40 portraits once, including pairs rejected via the neither button. Rejections affect pairs 21 onward. Reject both types of a skipped pair; when seven or more types have been rejected, permanently use all eight types for the remainder of that diagnosis. A diagnosis finishes after 20 positive choices; skipping does not add a vote.
- Keep draw progress, rejected types, reset status and choices in session storage, and preserve them across reloads. Use meaningful tests for draw/exclusion/scoring changes.
- Homepage visuals are `assets/female/female_011.png` and `assets/male/male_011.png`. The homepage promotion card shows an ensemble of eight characters, rendered by `scripts/render_promotion_card.cjs`. Keep `data/promotion_card.json`, the rendering template and Open Graph / X metadata in sync; visually check regenerated cards before marking `review_status` as checked.
- Results show all winning codes and matching gender/type characters. Under `例えば、こんな顔`, provide exactly five distinct current portraits for each winning type; tied types may use expandable groups. Character records are in `data/type_characters.js`; full generation prompts are in `data/character_prompts_v1.json`. The 16 original characters are presentation assets and must not affect scoring or appear on quiz choice cards.
- Preserve the 80 existing face/type URLs and their character/code cards (`scripts/render_share_cards.cjs`, `data/share_cards.json`). Results use `/share/letters/<gender>/<codes>/` with all nonempty subsets supported by `scripts/build_letter_share_pages.py`, including legacy letter-result URLs. Preserve the 54 existing OGP images tracked by `data/letter_share_cards.json`; additional type-tie pages use the homepage promotion card. Share URLs need no vote query; ignore old A/S/Q counts. Keep character/type/template hashes synchronized when regenerating cards.
- `/top/03/` and `/top/05/` serve separate static OGP HTML using the selected character OGP candidates, then redirect browsers to `/top/` with JavaScript. Keep their canonical / og:url unique. Do not replace these with a direct HTTP redirect or meta refresh to the common top, which would discard the separate metadata.
- For future face generation, prepare the full set of per-person prompts before generating. Describe fictional adult Japanese portraits, front-facing, neutral studio background, realistic editorial photography, age 25, no text, no watermark. Avoid age differences as a proxy for type. Generate each portrait independently and normalize with `scripts/normalize_face_asset.py` to 1200x1600. Keep the prompt and image hashes in the matching record.
